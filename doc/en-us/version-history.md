- `v1.3.1`: Fixed the custom storage-path migration. Changing the storage folder previously moved the five data files and `webdav_config.json`, stranding `images/`, `.sync_base/`, and `backups/` (bundles and blobs) at the old location. The worst consequence was silent: without `.sync_base/` the next sync has no base snapshot, so records other devices had deleted read as "new locally" and were re-uploaded, resurrecting deletions across every device. Migration now moves the **entire** storage folder except `storage_config.json` (which must stay put — it holds the path itself), so a data file added in a future release migrates with no code change. Existing destination files still win, and their source copies are now left in place rather than discarded. Shared logic lives in `myapps_data` `v1.0.1` as `migrateStorageContents`, covered by eight tests. Versions unified to `1.3.1+58` / MSIX `1.3.1.0` / installer `1.3.1`.

- `v1.3.3`: Weight reminder grace-window fixes — three defects that between them made the feature look absent and broken. The "Skip if already logged" control had existed since `v0.6.4` but was **unreachable**: `_showReminderSettings` opened a default modal bottom sheet, which Flutter caps at 9/16 of the screen height, and its body was an unscrollable `Column`, so the grace-window tile — the last child — was clipped out of view in `twice` mode and on short windows or large text scales. The sheet is now `isScrollControlled` with a `SingleChildScrollView` body, matching the six other sheets in the app (including the one 25 lines above it in the same file). Second, the desktop check anchored its window on `current`, the moment the 30-second loop happened to evaluate it, which *replaced* rather than extended the scheduled-time window: with a 3 h grace and an 08:00 reminder, a weigh-in at 06:00 stopped suppressing the reminder as soon as the check ran more than three hours later, so opening the app at 13:00 fired a reminder for a weight logged two hours *before* it was due. `shouldSkipWeightReminderAt` gained an optional `scheduledAt` anchor and the window is now the contiguous span `[scheduledAt − grace, firesAt + 1 min)`; `scheduledAt` is ignored unless it precedes `firesAt`, so the window can never widen forward past the fire moment, and the `v1.2.0` late-check case it was originally introduced for is preserved and guarded by a test. Mobile needed no change — it already anchors on the scheduled candidate, which is the literal semantics. Third, weight records written outside the weight page — from the intimacy body section and `POST /weight/add` — never notified `ReminderService`, so on mobile, where notifications are OS-scheduled ahead of time rather than decided at fire, a pending reminder fired against a stale grace window; both paths now call `refreshMobileSchedules()`. `_loadData` additionally gates the morning/evening reminder times on `reminderMode` exactly as `ReminderService._refreshWeightDataFromStorage` already did, so a file still carrying times for a disabled mode cannot push them into the scheduler. 11 new tests (161 total, all passing): 8 grace-window cases in a second group in `test/weight_reminder_grace_test.dart`, plus `test/weight_reminder_sheet_test.dart`, the repo's first page-level widget test — against the pre-fix sheet it reproduces the bug exactly, reporting a 134-pixel `RenderFlex` overflow in `twice` mode (62 in `once`) and the grace-window tile laid out at y=738 on a 640-pixel-tall surface, 98 pixels below the bottom edge. Because `testWidgets` bodies run in fake-async time, that test drives the page's real `dart:io` load chain through alternating `tester.runAsync` turns and pumps rather than `pumpAndSettle`, which never settles here. - `v1.4.0`: Adaptive-layout foundation and the shell's navigation rail — the first of three staged releases adopting the layout conventions worked out in MyAnime and written up in `ADAPTIVE-LAYOUT-GUIDE.md`. A new policy module, `lib/shared/utils/adaptive_layout.dart`, holds every threshold and every clamp behind named predicates and **imports nothing** — not `package:flutter/*` — so all six rules are pure functions checked at fifty viewports in milliseconds rather than five in seconds. Three separate questions get three separate rules and none is routed through another: `canSplitLayout(width, height)` asks about the whole screen's *shape* (600 dp wide, 480 dp tall, and a 0.82 width-to-height ratio, all three required); `useNavigationRail(screenWidth)` asks about width alone; `columnCapacity(contentWidth, minItemWidth:)` asks how many columns of a stated minimum fit, with one gap in the numerator so the arithmetic pays for the gaps *between* columns. The aspect test is the load-bearing one and exists for one device: a Galaxy Z Fold 8 unfolds to a 4:3 landscape panel, so held in portrait it is 3:4 — narrower relative to its height than the near-square Fold 7 it replaced — and one device therefore needs two different answers at one width, which no width threshold can produce. The cost is accepted up front: a tablet in portrait stays single-column too, because the rule is about shape, not device class. `ShellScaffold` now renders one destination list either as the existing bottom `NavigationBar` or, from 600 dp of width up, as a centred `NavigationRail` (`groupAlignment: 0`, since the default top alignment is for rails sitting under a leading menu button or FAB and this one has neither), wrapped so it scrolls rather than overflows at the compact heights where a rail can still appear. Both surfaces come from the new `_destinations` helper, so the Intimacy destination is filtered on the visibility flag in exactly one place and the two renderings cannot drift. The width-only rule is deliberate: a rail helps most precisely where the split rule refuses — a phone in landscape at 915 x 412, where a bottom bar spends 19% of the height on navigation while 915 dp of width sits unused. `lib/shared/widgets/adaptive_tile_grid.dart` adds `adaptiveTileRow`/`adaptiveTileRows` (a `Row` of `Expanded` cells rather than a `GridView`, because MyDay's lists are children of an outer scroll view and the finance list relies on `ListView.builder` virtualization; the single-column branch returns tiles untouched so existing `Dismissible` wrappers survive) and `listColumnsButton`, hidden rather than disabled when only one column fits. Four new l10n keys in all four ARBs. Two deliberate divergences from the guide are recorded in the new `doc/*/adaptive-layout.md`: MyDay needs no `shellListBottomInset`, because its `Scaffold` does not set `extendBody` and the `SizedBox(height: 80)` spacers are FAB clearance that is correct in both modes; and stored column preferences are reserved for the shell's own list surfaces. The Android manifest already declared `screenLayout|screenSize|smallestScreenSize|density`, which is what lets a fold resize the window without recreating the activity — now recorded in `platform-notes.md` with the reason. No page layouts changed yet and no data format changed, so the WebDAV golden transcripts are byte-identical. 30 new tests (191 total, all passing), including the repo's first pure layout-rule suite, whose viewports each name the real device they stand for, and a shell navigation widget test driven in Simplified Chinese because `flutter_test`'s default font renders Latin glyphs as full em squares and inflates them ~2.5x. - `v1.4.1`: The five shell pages adopt the adaptive-layout rules — stage two of three. **Todo** puts its three task sections side by side once the window has the shape and the width for it. The unit is deliberately the *section*, not the tile: each `TaskSectionWidget` wraps a shrink-wrapped `ReorderableListView`, and dragging a task between columns of one section is not meaningful, so the sections themselves are what go side by side, dealt round-robin into independently scrolling columns so a long Daily list cannot push Work off the bottom. **Finance** splits into a fixed left pane holding the month summary and the upcoming-renewal strip, and a right pane holding the transaction list; stacked, that summary spends up to a third of a phone's height before the first transaction appears. Its tiles also pack into columns *within each date group*, so a date header always spans the full width and one date's transactions can never sit beside another's. **Weight** puts the summary card beside the trend chart, behind a gate of three conditions rather than the guide's usual two: the shape rule, a width floor (280 + 380 + 12 = 672), and *at least two records* — because the chart renders nothing below that, and a summary card alone in a 280 pane beside a blank half is worse than the stacked layout it would replace. Whenever a block can render to nothing, it belongs in the gate. **Intimacy** keeps the month calendar and its cycle strips in a pane of their own beside the trend chart and the history; stacked, the calendar alone is most of a phone's height, so selecting a date scrolled the records it selected out of view. **Settings** becomes a real two-pane surface: the section list keeps its place on the left and the page a `›` row leads to fills the right, the way a system settings app behaves. All four of those pages — WebDAV, Backup, License, Privacy — are hosted unchanged, because a nested `Navigator` holding one route reports `canPop == false` and their app bars therefore grow no back arrow; every row goes through one `_open` method so the pushed and hosted modes cannot drift, and `_twoPane` is cached in `build` so what a tap does always matches what was on screen. Flutter's own `showLicensePage` stays a push in both modes, being a page this app does not own. Four device-local column preferences (`todoSectionColumns`, `financeListColumns`, `weightListColumns`, `intimacyListColumns`) join `storage_config.json`, which is never synced, because window size is a property of the device rather than of the account; each is clamped rather than rejected at render time, so a count pinned on a desktop survives a fold and comes back on unfolding, and the control that sets it is hidden — not disabled — wherever only one column fits.
